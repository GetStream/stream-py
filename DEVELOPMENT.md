# Getstream Python SDK

### Setup

Clone the repo and install dependencies. `uv sync` compiles the Rust extension
`getstream-rtc`, so install [rustup](https://rustup.rs) and a C compiler first
(macOS: `xcode-select --install`; Debian/Ubuntu: `apt install build-essential`):

```
git clone git@github.com:GetStream/stream-py.git
cd stream-py
(cd getstream-rtc && rustup toolchain install)   # the pinned Rust version
uv sync --no-sources --all-packages --all-extras --dev
cp .env.example .env   # fill in your Stream credentials
pre-commit install      # optional: enable commit hooks
```

### Running tests

Run `make help` to see all available targets. The most common ones:

```
make test          # non-video tests (chat, feeds, moderation, etc.)
make test-video    # video/WebRTC tests only
make test-all      # both of the above
```

Non-video and video tests are split because they require different Stream credentials.
The `MARKER` variable defaults to `"not integration"`, which is every test that does not
touch a live Stream app, so the default needs no credentials. Override it to run the ones
that do:

```
make test-integration              # runs both groups with -m "integration"
make test MARKER="integration"     # or target a single group
```

Two manual tests exist for local telemetry inspection (excluded from CI):

```
make test-jaeger       # requires local Jaeger (docker run ... jaegertracing/all-in-one)
make test-prometheus   # requires getstream[telemetry] deps
```

### What CI runs

| Trigger | What runs | Gates anything? |
| --- | --- | --- |
| Pull request | `run_tests.yml`: ruff, ty, the Rust checks of `getstream-rtc` (`cargo fmt`, `cargo clippy`, `cargo test --lib`), and `-m "not integration"` on five Python versions | yes, `🧪 Tests` is the required check |
| Pull request that changes `getstream-rtc/` or the wheel build | `rtc_wheels.yml`: builds and checks the `getstream-rtc` wheels for Linux x86_64, Linux aarch64 and macOS arm64; uploads nothing | no |
| Daily at 09:00 UTC | `run_integration.yml`: `-m integration`, both credential sets | no |
| Release PR merged | nothing on the default branch, the unit lane on `N.x`; `release.yml` builds each `getstream-rtc` wheel again from the tag and checks it before it uploads it | `N.x` only; a failed wheel stops the `getstream` upload |

`@pytest.mark.integration` means one thing: the test talks to a live Stream app. The unit
lane therefore runs with no credentials, no `environment:` and no `STREAM_*`. Keep it that
way. A fork PR gets no secrets and still goes green, and a live test added without the
marker fails in CI instead of quietly passing on someone else's credentials.

Integration gates nothing, anywhere. It runs against an app five SDK repos share, so
another repo's run or a backend regression can redden it with nothing wrong here. It does not
run before a tag either. A red daily run opens an issue titled "Daily integration run is
red". Fix it, do not route around it.

A Release PR skips the lane and `🧪 Tests` passes in seconds on a `skipped` result. The skip only applies while the diff is nothing but what release-please writes, down to the version line in each version file, so a code or dependency change pushed onto a Release PR by hand runs the unit lane like any other PR. Merging it tags and publishes with no further test run: it adds only the version bump and changelog to an already-tested `main`. A hotfix release from `N.x` runs the unit lane first, since its commits were pushed without a PR.

### Linting and type checking

```
make lint        # ruff check + format check
make typecheck   # ty type checker (excludes generated code)
```

To auto-fix lint issues and format:

```
make format
```

Run lint, typecheck, and non-video tests in one go:

```
make check
```

### Code generation

```
make regen    # regenerate OpenAPI + WebRTC protobuf code (SPEC_TAG=openapi-vX picks the spec)
```

### Legacy: dev.py

`dev.py` is an older CLI tool that predates the Makefile. It still works but does not
handle the video/non-video test split or manual test exclusions. Prefer `make` targets.

## Release

Releases are generated by release-please and published by CI. See the Releases
section of `README.md`.

Do not tag or publish by hand. A hand-pushed `vX.Y.Z` tag collides with
release-please's own tagging and leaves `.release-please-manifest.json` behind the
released version.

## OpenAPI & Protobuf

Most API endpoints use OpenAPI definitions, and part of the video endpoints use Protobuf. `./generate_webrtc.sh` regenerates the Protobuf code by hand.

The OpenAPI client regenerates itself on every chat production release:

1. chat attaches its `openapi` generator to the release and publishes the matching `openapi-vX` spec release in [protocol](https://github.com/GetStream/protocol).
2. protocol notifies this repo, and the **Regenerate** workflow opens one PR from `regen/auto`, titled `feat: regenerate client from openapi-vX`. Its `BEGIN_COMMIT_OVERRIDE` block lists the changelog lines.
3. Once the required checks pass and the **Regen integration** run passes on the PR's head commit, the PR merges itself, and release-please adds those lines to the Release PR. Merging the Release PR ships, as described in `README.md`.

A regen PR waits for a human when its changelog carries a `BREAKING CHANGE:` footer, when the `Breaking changes check` finds an approved breaking change in the new spec, or when a required check fails. For each approved breaking change with wire lines, the regen writes `BREAKING CHANGE:` footers from the lines chat allowlisted and titles the PR `feat!:`, so the check passes and the PR only waits for a human to merge it. A ticket chat approved for getstream-go only has no Python lines, so the check fails until a human names it in the PR body, also on a `feat!:` PR. Because Python callers pass arguments by position or by keyword, the regen also compares the generated methods before and after, and writes a footer for each removed method and each method whose arguments were renamed or moved, even when the spec did not change them. Only `getstream-sdk-bot` can push to `regen/**`.

### Manual cases

- **Regenerate now:** run **Regenerate** from the Actions tab with an `openapi-vX` tag, or leave it empty for the latest. Locally, `SPEC_TAG=openapi-vX ./generate.sh` does the same with the generator built from a `../chat` checkout at that tag.
- **A breaking change that breaks this SDK:** when the regen titled the PR `feat!:`, review its footers. It moves on to each newer spec until you rename the PR or edit its body, which keeps it on the spec you judged. Otherwise add `!` to the PR title, and before `END_COMMIT_OVERRIDE` add a blank line and `BREAKING CHANGE: <what breaks for customers>`. Then merge it yourself in a breaking-change window, with a `MIGRATION_vX_to_vY.md` guide.
- **An approved breaking change that does not break this SDK:** label the PR `sdk-not-breaking` and name each ticket the check lists in the PR body. When the regen titled it `feat!:`, also drop the `!` and delete the entries that carry a `BREAKING CHANGE:` footer. The next Regenerate run merges it, daily at 06:23 UTC or when you start one.
- **Failed integration tests:** the tests share their Stream app with other SDKs' CI, so the Regenerate run reruns a red or cancelled **Regen integration** run once by itself, and merges the PR when the rerun passes. If the rerun is red too, fix the cause or rerun it again; a pass merges the PR. If no run started for the PR's head commit, start **Regen integration** on `regen/auto` from the Actions tab.
- **Rewrite a changelog line:** edit the `BEGIN_COMMIT_OVERRIDE` block in the merged PR's body, then run the **Release** workflow with no input to rebuild the Release PR. Keep ticket IDs out of PR titles, because a title becomes a changelog line.
